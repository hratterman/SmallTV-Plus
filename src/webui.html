Push a message

Anything on your network can interrupt the screen with a banner:
curl -X POST http://smalltv.local/notify \
  -d '{"text":"Build finished","sec":8,"color":"#3fb950"}'
sec defaults to 8 (max 120) and color is any hex like #f7931a; only text is required. The banner takes over whichever mode is showing, then hands the screen back. A tap on the lid clears it early.

Saved networks

2.4 GHz only. Up to 4 networks; at boot the device joins the strongest one it can see. Tap a scan result to fill a row. Leave a password blank to keep the stored one.

Device name

Reachable as http://<hostname>.local via mDNS. Running several SmallTVs? Give each its own name (smalltv-desk, smalltv-shelf) so browsers and the clawdmeter daemon's --push-to reach the right device. Saving a new name reboots the device.

Setup hotspot (AP)

The AP appears when no WiFi is configured or the connection fails. It also comes back up alongside the connection if the device gets stuck behind a captive portal, so there is always a way to reach these settings.

Captive portal

Route out: -
Hotel and conference networks hand out an IP and then block everything until you click Connect in a browser. The device checks for a real route out and, when it finds a portal, fetches its page and submits the first form — which is what that button does. Nothing here is needed on a normal network.
Portal needs a hand Some portals build their form in JavaScript, and there is nothing in the HTML for the device to submit. Open the portal on a laptop, accept it with devtools’ Network tab recording, right-click the accept request → Copy → Copy as cURL, and take the URL and the --data body from it. The device submits the form itself, so hidden fields carry its own address rather than your laptop’s — that is what authorises the cube rather than re-authorising the laptop. Plain http:// only: a portal cannot intercept HTTPS, so it just hangs instead of answering.

Mode

Pick the active feature, then configure it in its own tab. The ticks above govern both the carousel rotation and which modes a tap on the lid steps through — untick one and it stops appearing either way. A mode you are not showing does no work: only the active mode fetches. Spotify is the exception, since it has to keep watching in order to take over when you press play.

Ambient

Five patterns with no network involved. Long-press the lid pad to step to the next one by hand.
Unticking them all is ignored rather than obeyed — that would leave a black screen with nothing to say why. To turn ambient off entirely, untick it in the carousel above.
Ambient is meant to be watched rather than read, so it gets its own dwell instead of the carousel's. The other screens keep the shared one above.

Work mode

Masking is whole-word and case-insensitive, so a blocked ass does not turn bassline into asterisks. An explicit track still shows its cover, artist and progress — only the title is replaced, which is enough to know what is playing without it announcing itself across the room.
Mining is refused outright while this is on, whatever the Miner tab says: it runs on someone else’s network and someone else’s electricity, which is a policy question rather than a preference.

Clock & night mode

Clock: -
During the night window the screen goes fully off (ignoring the brightness above), rendering stops, and the other modes stop fetching — no ticker requests, no radar polling, no Spotify checks. Only the miner keeps running. The web UI stays reachable, so /api/status still reports the hashrate, and a tap on the lid brings the screen back for two minutes. A pushed notification still comes through. Needs internet once to set the clock over NTP (no on-screen clock, this just drives the schedule). While the window is active it overrides the brightness and auto-brightness above. Times are local to the selected timezone; DST is handled automatically. After a reboot the schedule resumes once the clock re-syncs, so the screen may show normal brightness for a few seconds.

Rotation & data

Chart timeframe: the change, arrow, colors, and chart cover the same span, so they agree. Needs chart data (2+ points); without it the device falls back to the 1-day change. At 1 day it measures from the session's first data point, so overnight gaps are not counted. 1 day: the classic change vs the previous close, which can point the other way than a longer chart.

cash.ch symbol finder

Searches cash.ch from your browser and turns the result into the listing key the ticker needs. Click a match to add it as a ticker.

Claude usage

Runs on the PC-side clawdmeter-daemon, which reads your Claude usage and sends it here. Pull: set the Usage URL to the daemon. Push: leave it blank and run the daemon with --push-to <hostname>.local (for networks where the device cannot reach the PC). Running several SmallTVs? Give each a unique hostname in the WiFi tab so every PC pushes to its own device. Idle animation plays until data arrives.

Home location

The radar centres on this point. Decimal degrees, e.g. 52.3676, 4.9041. Leave at 0/0 and the screen prompts you to set it.

Solo mining

Hybrid puts core 0 on the ESP32's SHA peripheral and leaves core 1 on software; measured on this board that is roughly 380 KH/s vs 50 KH/s, so it is the default. Only one core can hold the peripheral at a time, so this is the fastest arrangement available. The Status tab reports each core separately if you want to re-measure. The peripheral is checked against the software result before its first share and falls back automatically if they disagree. Switching takes effect within a second, no reboot. Solo lottery mining against a stratum pool (default solo.ckpool.org:3333): jobs come from the pool, and in the astronomically unlikely event of a found block it pays out to this address. Mining runs in the background whenever enabled and an address is set, even while another mode is on screen. It uses otherwise-idle CPU; display and web UI keep priority.

Clock face

Time comes from NTP using the timezone set on the Display tab, so DST is handled for you. The clock only syncs when something needs it — selecting this mode is enough. A dot appears top-right if the last sync is too old to trust. Long-press the lid pad to flip 12/24-hour.

Now playing

Linking, once. Spotify only allows HTTPS or loopback redirect URIs, and the cube can offer neither, so the browser half runs on your computer:
1. developer.spotify.com/dashboard → Create app, redirect URI http://127.0.0.1:8888/callback
2. python3 tools/spotify_auth.py --id <CLIENT_ID> --secret <CLIENT_SECRET>
3. Paste all three values above and save.
Only user-read-currently-playing is requested — it can read what is playing and nothing else. Revoke any time at your Spotify apps page. The secret and token are never sent back to this page once saved; leave them blank to keep what is stored.

Next obligation

Linking, once. The cube reads your next two days and shows the nearest event with a countdown. Recurring events are expanded by the provider, not the cube.
Google, the easy way: open the hosted tether page and use its Link Google Calendar card — the consent runs in the browser and the token lands on the cube over the cable (or is shown for pasting here). No terminal.
Google, by script: console.cloud.google.com → OAuth client, type Desktop app; enable the Calendar API; then python3 tools/calendar_auth.py google --id <ID> --secret <SECRET>
Microsoft: portal.azure.com → App registration, enable Allow public client flows; then python3 tools/calendar_auth.py microsoft --id <ID> and follow the code it prints.
Or skip the script for Microsoft: paste just the client ID above, save, and press Link with Microsoft — the cube fetches a short code and shows it here and on its own screen; type it at the address given and you are done. No terminal anywhere.
Only read access is requested (calendar.readonly / Calendars.Read). Works over the tether too — both providers answer a browser. Secrets are never sent back to this page once saved; leave them blank to keep what is stored.

Lid button

The pad on top of the cube is wired to one of the ESP32's capacitive touch pins, but nothing documents which. Press Find the pad, then tap the lid a few times — whichever channel reacts is yours. The live readings below drop when a channel is touched.

Update from GitHub

Installed: -
Pulls the newest release straight from the GitHub repo. HTTPS OTA is tight on the ESP8266; if it fails, use the manual upload below.

Manual update (OTA)

Upload firmware.bin from the releases page or a local build. The device reboots when done. Not firmware.factory.bin — that one is the whole-flash image, for flashing over USB.

Settings backup

The export is the device's config.json, including WiFi passwords and the Spotify refresh token in clear text; treat the file accordingly. Import applies everything and reboots.
